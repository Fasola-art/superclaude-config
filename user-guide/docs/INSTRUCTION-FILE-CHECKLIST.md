# 전문가용 지침 파일 설계 마스터 체크리스트

> **목표**: 사용자가 **일관되고 예측 가능한 고품질 결과**를 얻도록 보장하는 지침 설계

**버전**: 2.0 | **최종 수정**: 2026-02-01

---

## ⚡ 퀵 스타트 (5분 체크리스트)

> 이 8개 항목만 완료하면 최소 기능 지침 파일 완성 (70점 이상 보장)

| # | 항목 | 테스트 방법 |
|---|------|-------------|
| 1 | **목표 1문장 정의** | "사용자는 ___를 얻는다" 완성 가능? |
| 2 | **성공 기준 측정 가능** | 숫자/퍼센트가 있는가? |
| 3 | **섹션 3-5개 이내** | `##` 헤더 개수 확인 |
| 4 | **각 섹션 독립적** | 임의 섹션 선택 → 혼자 이해 가능? |
| 5 | **모든 플레이스홀더에 예시** | `<` 또는 `{` 검색 → 모두 예시 있음? |
| 6 | **필수/선택 명확** | 모든 항목에 ✅/🔄 또는 필수/선택 표시? |
| 7 | **표/리스트 비율 60%+** | 표가 산문보다 많은가? |
| 8 | **자가 체크 존재** | 문서 끝에 체크리스트 있음? |

```
✅ 8개 모두 체크 → 사용 가능
❌ 누락 항목 있음 → 아래 전체 체크리스트 검토
```

## 🤖 Phase 0: LLM 최적화

> LLM이 지침을 효과적으로 처리하기 위한 핵심 고려사항

### 토큰 배치 전략
- [ ] **핵심 지침 상위 500 토큰 내 배치**: 가장 중요한 규칙이 문서 최상단에?
- [ ] **우선순위 순서대로 배치**: 높은 우선순위 = 앞쪽 위치?
- [ ] **총 길이 8K 토큰 이하**: 긴 문서는 후반부 무시 위험?

### 지시 스타일
- [ ] **긍정형 우선**: "X를 해라" > "Y를 하지 마라"?
- [ ] **명령형 동사**: 직접적 동사 (작성, 생성, 분석) vs 수동태?
- [ ] **구체적 > 추상적**: 구체적 예시 vs 모호한 설명?

### 포맷 최적화
- [ ] **출력 포맷 예시**: 원하는 출력 형식이 데모되어 있는가?
- [ ] **Few-shot 예시**: 1-2개의 완전한 입력→출력 예시 제공?
- [ ] **구분자 일관성**: 동일한 마커 (`---`, `###`) 전체 사용?

## 🎯 Phase 1: 설계 전 전략 수립

### 목표 명확화
- [ ] **Primary Outcome**: 최종 결과물이 한 문장으로 정의?
  - 예: "투자자 제출용 PRD 문서" / "프로덕션 배포 가능한 코드"
  - **테스트**: "사용자는 ___를 받는다" 10단어 이내로 완성 가능?
- [ ] **Success Criteria**: 숫자로 측정 가능?
  - 예: "15개 섹션 중 12개 이상 작성" / "테스트 커버리지 80% 이상"
  - **테스트**: 최소 하나의 숫자 또는 퍼센트 포함?
- [ ] **Failure Cases**: 중단 또는 경고 시점이 정의?
  - 예: "시장 규모 산출 불가 시 중단" / "API 스펙 충돌 시 경고"

### 사용자 세그먼트
- [ ] **Target User**: 주 사용자가 명확히 정의?
  - 예: "스타트업 PM", "기업 전략팀"
- [ ] **Usage Context**: 사용 상황이 명시?
  - 예: "투자 유치용 PRD", "내부 승인용 기획서"

### 제약 조건
- [ ] **토큰 제한**: LLM 컨텍스트 윈도우 고려?
- [ ] **시간 제약**: 현실적인 예상 완료 시간?
- [ ] **인지 부하**: 청크당 정보량 7±2개 이내?

## 🏗️ Phase 2: 구조 설계

### 모듈화 (독립성)
- [ ] **자기완결성**: 각 모듈이 단독으로 이해 가능?
  - **테스트**: 단일 섹션만 LLM에게 주고 → 컨텍스트 없이 실행 가능?
- [ ] **의존성 명시**: 선행 작업이 명시적으로 표기?
- [ ] **Fallback 전략**: 데이터 없을 때 대안 제시?

### 모듈화 (응집성)
- [ ] **단일 책임**: 각 섹션이 하나의 주제만 다룸?
- [ ] **논리적 그룹핑**: 관련 항목이 함께 묶임?

### 계층 구조
- [ ] **깊이 제한**: 최대 4단계 (# → ## → ### → ####)?
- [ ] **폭 밸런스**: 한 단계에 5-9개 항목?
- [ ] **대칭성**: 동일 레벨 항목이 비슷한 무게?

### 일관성
- [ ] **템플릿 패턴**: 모든 분석 섹션이 동일 구조?
- [ ] **메타데이터 통일**: 평가 기준이 일관됨?
  ```markdown
  영향도: H / M / L
  우선순위: P0 / P1 / P2
  상태: ✅ 완료 / 🔄 진행중 / ❌ 미착수
  ```
- [ ] **용어 사전 정의**: 핵심 용어가 정의되고 일관 사용?
- [ ] **시각적 일관성**: 이모지/표 포맷 표준화?

### 확장성
- [ ] **버전 표기**: 문서 버전이 명시?
- [ ] **플러그인 구조**: 새 섹션이 기존 섹션에 영향 없음?
- [ ] **커스터마이징 포인트**: 변수가 플레이스홀더로 분리?

## 🎨 Phase 3: 인터페이스 설계

### 가독성

  - **테스트**: 헤더만 읽고 → 문서 요약 가능?

- [ ] **예상 시간**: 섹션별 작업 시간 명시?

### 사용성
- [ ] **점진적 공개**: 복잡도가 단계별로 구분?
- [ ] **필수/선택 명확**: 필수 필드가 표시?
- [ ] **예시 제공**: 모든 플레이스홀더에 예시?
- [ ] **품질 기준**: 합격/불합격 기준 명시?

## 🔬 Phase 4: 품질 보증

### 완전성
- [ ] **Happy path**: 이상적 시나리오 100% 커버?
- [ ] **Edge cases**: 예외 처리 방법 제공?
- [ ] **Negative cases**: "하지 말아야 할 것"도 명시?

### 정합성
- [ ] **순환 참조 없음**: A→B→C→A 의존성 없음?
- [ ] **모순 없음**: 상충하는 지시 없음?
- [ ] **용어 일치**: 같은 개념 = 같은 이름?

### 보안 (신규)
- [ ] **민감 데이터 처리**: PII, 시크릿, 자격증명 처리 지침?
- [ ] **출력 정화**: 안전한 출력 생성 가이드?
- [ ] **인젝션 방지**: 프롬프트 인젝션 방어책?

### 에러 복구 (신규)
- [ ] **실패 모드 정의**: 문제 발생 시 어떻게 되는가?
- [ ] **재시도 가이드**: 부분 실패에서 복구 방법?
- [ ] **에스컬레이션 경로**: 언제 사용자에게 도움 요청?

### 테스트 가능성
- [ ] **측정 가능 목표**: 성공을 숫자로 확인?
- [ ] **샘플 출력**: 올바른 결과 예시 제공?
- [ ] **자가 진단 체크리스트**: 각 섹션에 자가 점검?

## 📝 Before/After 예시

### 예시 1: 목표 정의

**❌ Before (모호함)**
```markdown
## 목표
사용자가 좋은 문서를 만들도록 돕는다.
```

**✅ After (측정 가능)**
```markdown
## 목표
**Primary Outcome**: 프로덕션 준비된 API 문서
**Success Criteria**:
- 엔드포인트 100% 커버리지
- 모든 파라미터에 예시 포함
- 에러 시나리오 응답 코드 포함
**Failure Case**: OpenAPI 스펙 없으면 중단
```

### 예시 2: 섹션 구조

**❌ Before (산문 중심)**
```markdown
## 시장 분석
경쟁사, 시장 규모, 트렌드를 분석합니다.
타겟 사용자와 그들의 니즈를 고려합니다.
가격 전략과 시장 포지셔닝을 검토합니다.
```

**✅ After (표 중심)**
```markdown
## 시장 분석

| 항목 | 필수 출력 | 예시 |
|------|----------|------|
| TAM | $ 수치 + 출처 | "$50B (Gartner 2025)" |
| 경쟁사 | 상위 3개 + 차별점 | "경쟁사 A: X 기능 없음" |
| 타겟 세그먼트 | 인구통계 + 페인포인트 | "Series A 스타트업, 10-50명" |
```

## 🎯 전문가 원칙

> **"Phase 1 (전략) + Phase 2 (구조) 완벽 = 80점 보장"**

### 85점 이상 지침 파일의 3가지 핵심

1. **모듈화 설계** (가장 중요)
   - 각 섹션 독립 작동
   - 표 중심 구조
   - 통일된 메타데이터

2. **일관성**
   - 동일 패턴 반복
   - 용어 사전 먼저 정의
   - 시각적 요소 표준화

3. **LLM 인식 구조**
   - 핵심 내용 상단 배치
   - 긍정형 지시 우선
   - 구체적 예시 제공
